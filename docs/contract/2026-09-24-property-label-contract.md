# Контракт: у свойства компонента появились «Имя» (`label`) и «Имя для шлюза» (`gateway_name`)

Дата: 24.09.2026. Бэкенд — ветка `feat/property-label` (задача `scada-f3hx`). Покрыто IT
(`PropertyLabelIT`), полный прогон `editor` и `runtime` — см. отчёт в задаче.

## Коротко

У свойства теперь три разных имени, у каждого своя работа:

| Поле | Подпись в UI | Для чего | Ограничения |
|---|---|---|---|
| `name` | «Название» (как сейчас) | адрес свойства для скриптов: `OP.V`, `writeTag('OP', …)`, `component_property_name` у биндинга | уникально в компоненте, должно быть идентификатором JS (без пробелов) |
| `label` **новое** | «Имя» | человеческое имя для оператора: «F4 Текущий приемник, № танка» | любое, может быть пустым |
| `gateway_name` **бывшее `description`** | «Имя для шлюза» | то, что раньше писали в «Описание» | любое, может быть пустым |

Бэкенд совместим со старым фронтом: принимает `description` вместо `gateway_name` и продолжает
отдавать `description` (то же значение, что `gateway_name`). Ломаться ничего не должно, пока фронт
не перешёл. **После перехода `description` из ответа уберём** — отдельным сообщением.

## Формат на проводе

### Приём — `POST`/`PUT /api/editor/components`, `POST`/`PUT /api/editor/templates`, свойства

```json
{
  "name": "OP",
  "label": "F4 Текущий приемник, № танка",
  "gateway_name": "OBJECT10.S_PAR_F[ 4 ]",
  "property_type": "Тег",
  "tag_id": "BN1.Танки-нормализации-молока.GR1.LINE_IN.S_PAR_F[ 4 ]",
  "value_type": "integer"
}
```

- `label`, `gateway_name` — необязательные, `null`/отсутствие = пусто.
- `description` принимается как старое имя `gateway_name` (Jackson-алиас). Прислать оба — не нужно.

### Ответ — везде, где есть свойства (компоненты, шаблоны, версии, дерево проекта из `runtime`)

```json
{
  "id": 5872, "name": "OP",
  "label": "F4 Текущий приемник, № танка",
  "gateway_name": "OBJECT10.S_PAR_F[ 4 ]",
  "description": "OBJECT10.S_PAR_F[ 4 ]",
  "property_type": "Тег", "tag_id": "…", "value_type": "integer", "…": "…"
}
```

`description` — устаревшее зеркало `gateway_name`, читать не нужно.

Дерево проекта для монитора (`POST /api/runtime/sessions` → `projectTree`) тоже несёт `label` и
`gateway_name`: `runtime` пересобирает его своим DTO, поля туда добавлены.

### Побочный эффект

Новые поля попадают в снимки версий сцены. Первое сохранение каждой сцены после выкатки запишет
новую версию, даже если по смыслу ничего не поменялось (у снимка изменился состав полей). Старые
снимки восстанавливаются как прежде: их `description` читается в `gateway_name`.

## Что сделать на фронте

Сверено с фронтом 24.09.2026 (только чтение).

### 1. Типы — `src/types/tags.types.ts`

В `PropertyCreateRequestDto` заменить `description: string;` на:

```ts
  /** Человеческое имя для оператора («Опции» монитора). name занят скриптами. */
  label?: string | null;
  /** Имя для шлюза (до 24.09.2026 — description). */
  gateway_name?: string | null;
```

### 2. Преобразование ответа — `src/lib/transformElements.ts`

В типе свойства (стр. ~22) `description: string | null;` → `label: string | null; gateway_name: string | null;`
и там, где поля переносятся в элемент, переносить оба. Если где-то читается `description` у
свойства — брать `gateway_name`.

### 3. Форма свойства — `src/components/ui/OpenChooseTagModal.tsx`

- Поле «Описание» (стр. ~253–265) переименовать в **«Имя для шлюза»**, состояние
  `description` → `gatewayName`, в `payload` — `gateway_name: gatewayName.trim()`.
- Добавить поле **«Имя»** (`label`) рядом с «Название»: подсказка «Как свойство видит оператор»,
  в `payload` — `label: label.trim() || null`.
- При открытии на правку — `property?.label`, `property?.gateway_name ?? property?.description`
  (второе — на случай данных из старого ответа).

### 4. «Опции» монитора — `src/components/monitor/ElementOptionsModal.tsx`

Подпись строки (стр. ~316–318) и сообщения тостов (`«${…property.name}»`) показывают `name`.
Показывать имя для человека:

```tsx
{p.label?.trim() || p.name}
```

Технический `name` можно оставить мелким серым рядом с путём тега — он нужен при отладке скриптов.

### 5. Ячейки таблиц — `src/lib/editor/tableBindings.ts`, `src/types/binding.types.ts`

Источник поля ячейки `"description"` («Описание») заменить на `"gateway_name"` («Имя для шлюза») и
добавить `"label"` («Имя»). Уже сохранённые привязки с `field: "description"` продолжают работать,
если в `staticFieldText` оставить ветку `case "description": return prop.gateway_name ?? "";`.

## Как проверить

1. Открыть свойство в редакторе, заполнить «Имя» и «Имя для шлюза», сохранить сцену, открыть заново —
   оба поля на месте.
2. Монитор → ПКМ на элементе → «Опции»: строка подписана «Именем»; у свойства без «Имени» — `name`.
3. Старая сцена, сохранённая до перехода, открывается и сохраняется без потери «Имени для шлюза».
