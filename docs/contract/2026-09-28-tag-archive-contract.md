# Архив тегов: тренды, воспроизведение, журнал действий — контракт для фронта

Дата: 28.09.2026. Бэкенд — `runtime` (коммиты `a33d63c..e7866d7` в `main`). Дизайн —
`docs/superpowers/specs/2026-09-28-tag-archive-design.md`.

Что появилось: `runtime` пишет в архив **только изменения** значений всех тегов своих топиков
(глубина 30 дней), отдаёт историю для трендов и воспроизведения сцены и ведёт журнал действий
оператора. Что нужно на фронте — по разделам ниже.

Все эндпоинты — через gateway (`/api/runtime/**`), любой экземпляр `runtime` отвечает по всему
архиву (база общая). Тег везде — путь канала, как в `component_property.tag_id`.

---

## 1. Настройка тренда (редактор)

Хранится существующими средствами `editor`, новых эндпоинтов нет.

**Перо = свойство компонента** `type = 'trend'`:

| Поле свойства | Значение |
|---|---|
| `name` | `pen1`, `pen2`, … — ключ пера |
| `label` | подпись пера в легенде |
| `property_type` | `Тег` |
| `tag_id` | путь тега |
| `value_type` | `float` (bool/integer тоже допустимы — рисуются ступенькой) |

Тег свойства попадает в индекс проекта, поэтому `runtime` сам шлёт его изменения в монитор
(`UPDATE.tags`) — для живого окна отдельный канал не нужен.

**Оформление — в `image` базового состояния**, ключ `trend` (базовый ключ, как `monitorMenu`:
добавить `trend` в `BASE_ONLY_KEYS`):

```json
"trend": {
  "window": 1800,
  "step": 300,
  "pens": {
    "pen1": { "color": "#3b82f6", "min": 0, "max": 100, "width": 2 },
    "pen2": { "color": "#ef4444", "min": 0, "max": 6,   "width": 2 }
  }
}
```

| Поле | Смысл |
|---|---|
| `window` | временной промежуток живого окна, секунды |
| `step` | шаг сетки и подписей времени по оси X, секунды. На данные не влияет |
| `pens.<name>` | оформление пера; связь со свойством — по `name` |
| `pens.<name>.min` / `max` | масштаб пера по Y — свой у каждого пера |
| `pens.<name>.color` / `width` | цвет и толщина линии |

Свойство без записи в `pens` — цвет по умолчанию и масштаб по данным; запись в `pens` без
свойства игнорируется. Прежние общие `min`/`max` компонента тренда заменяются масштабом пера.
Демонстрационная синусоида в `TrendShapeElement` заменяется данными.

## 2. Тренд в мониторе

1. При открытии сцены — один запрос истории за `[now − window, now]` (раздел 3) по тегам всех
   перьев тренда.
2. Дальше точки дописываются из `UPDATE.tags` живого WebSocket монитора.
3. Оператор меняет окно, масштаб, отматывает назад — **только у себя на экране, без
   сохранения**; закрыл сцену — тренд вернулся к настройке из редактора. Отмотка назад — новый
   запрос раздела 3 за нужный период.

## 3. `GET /api/runtime/archive/values`

```
GET /api/runtime/archive/values?tag=<путь>&tag=<путь>&from=<ISO-8601>&to=<ISO-8601>&maxPoints=1000
```

| Параметр | |
|---|---|
| `tag` | повторяется; от 1 до 20 тегов (`runtime.archive.max-tags-per-request`) |
| `from`, `to` | ISO-8601 (`2026-09-28T09:00:00Z`); `from < to`, `from` не раньше 30 дней назад |
| `maxPoints` | необязательный, по умолчанию 1000, не больше 5000 |

**200:**

```json
{
  "from": "2026-09-28T09:00:00Z",
  "to":   "2026-09-28T10:00:00Z",
  "series": [
    {
      "tag": "Барановичи-1.BN1_MCA1.V_ST_1.LINE1V0.ST",
      "initial": { "ts": "2026-09-28T07:12:40Z", "value": 1.0, "good": true },
      "points":  [ { "ts": "2026-09-28T09:15:02.113Z", "value": 0.0, "good": true } ],
      "aggregated": false
    }
  ]
}
```

- `initial` — значение **на момент `from`** (последняя точка до него); `null` — в архиве его нет.
  С него линия тренда начинается у левого края.
- `points` — изменения внутри периода по возрастанию `ts`. Между точками значение **стоит**
  (архив хранит только изменения) — рисовать ступенькой, а не соединять наклонной линией.
- `value` — число (`bool` приходит как `1.0` / `0.0`), строка, или `null` при `good: false`
  (обрыв связи — рисовать разрывом).
- `aggregated: true` — числовой тег прорежен: период разбит на корзины, из каждой пришли точки
  минимума и максимума (пики сохранены). Недостоверные точки приходят всегда.
- Неизвестный путь — серия с `initial: null` и пустыми `points`, не ошибка.
- **400** — больше 20 тегов, `from >= to`, `from` старше 30 дней.

## 4. Режим «Архив» — воспроизведение сцены

Монитор открывает сцену в режиме «Архив»: **живой WebSocket не подключается**, клики
выключены (ACTION отправить всё равно некуда — записи в ПЛК невозможны по построению).

```
POST /api/runtime/archive/replay
{ "tags": ["путь1", "путь2", "…"], "from": "<ISO>", "to": "<ISO>", "after": null }
```

**200:**

```json
{
  "initial": { "путь1": { "ts": "…", "value": 1.0, "good": true }, "путь2": null },
  "changes": [ { "ts": "2026-09-28T09:15:02.113Z", "tag": "путь1", "value": 0.0, "good": true } ],
  "next": "MTc1OTA0Njk1MjExMzAwMDoxMg"
}
```

- `tags` — все теги сцены (список даёт фронт, сцена у него загружена); до 5000.
- `initial` — состояние всех тегов на момент `from`; есть **только в первой странице**
  (`after: null`), в следующих — `null`. `null` у тега — значения нет.
- `changes` — по возрастанию `ts`, до 50 000 строк на страницу.
- `next` — непрозрачный курсор: следующая страница — тот же запрос с `"after": next`. `null` —
  период выдан до конца. Пока играет страница, стоит подтягивать следующую.
- Перемотка за пределы загруженного — новый запрос с `from` = точка перемотки, `after: null`.
- Значения подаются в рендер **тем же путём, что `UPDATE.tags`** живого монитора — биндинги
  рисуют схему как обычно. Ускорение и пауза — на фронте.
- Раз в сутки у каждого тега есть опорная точка — строка с тем же значением, что и было;
  применяется без видимого эффекта.
- **400** — больше 5000 тегов, неверный период, битый `after`.

## 5. Журнал действий оператора

```
GET /api/runtime/actions?projectId=989&from=<ISO>&to=<ISO>&username=ivanov&kind=ACTION&page=0&size=100
```

`from`, `to` — обязательны; остальное — фильтры. Ответ — массив, новые сверху:

```json
[{
  "ts": "2026-09-28T09:15:02.101Z",
  "username": "ivanov",
  "projectId": 989,
  "kind": "ACTION",
  "componentId": 16024,
  "component": "Танк_Мойка",
  "target": "Открыть клапан",
  "tags": null,
  "outcome": "OK",
  "error": null
}]
```

| `kind` | Что это | `target` | `tags` |
|---|---|---|---|
| `ACTION` | нажатие в мониторе (скрипт компонента) | имя скрипта | `null` — что записал скрипт, видно в архиве |
| `PROCEDURE` | управление процедурой рецепта | `start <рецепт>`, `pause …`, `resume …`, `abort …`, `confirm шаг N …`, `jump шаг N …` | `null` |
| `TAG_WRITE` | прямая запись из «Опций» компонента | `null` | `[{"tag": путь, "value": "…"}]` |

`outcome` — `OK` или `ERROR` (текст в `error`; у `TAG_WRITE` — теги, которые контроллер не
подтвердил). `size` — до 1000. **400** — `from >= to`.

## 6. Флаг `logging` у свойства

Галочка в окне выбора тега (`OpenChooseTagModal`, поле `logging`) **ничего не делает**: архив
пишет все теги топиков без исключений. Галочку стоит убрать (на бэке — задача в beads на
удаление поля).
