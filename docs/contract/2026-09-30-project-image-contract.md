# `image` проекта (общие закрепления схем) — контракт для бэка

Дата: 30.09.2026. Фронт готов и работает по-старому (localStorage), пока этого нет на бэке.

## Зачем

Закреплённые схемы — вкладки быстрого доступа над холстом — сейчас хранятся в браузере: у каждого
пользователя и на каждом компьютере свои. Нужно, чтобы инженер закреплял схемы проекта один раз
для всех — для коллег в редакторе и для операторов в мониторе. Храним их в `image` проекта: он
приходит вместе со списком проектов, отдельного запроса при выборе проекта не нужно.

Сейчас так сделать нельзя:

- проект создаётся **без состояний** (`ComponentServiceImpl.createProject`: `states = []`), `image`
  у него нет;
- список проектов (`GET /api/editor/components/projects`) отдаёт только `{id, name}`;
- записать `image` проекта нечем: `PUT /api/editor/components` требует `scene_id`, адресующий
  сцену, и считает тело всей сценой.

## 1. Чтение — `image` в списке проектов

```
GET /api/editor/components/projects
→ 200 [
    {"id": 989, "name": "Нормализация", "image": {"pinnedScenes": {"v": 1, "ids": [12, 7, 30], "recipesIndex": 3}}},
    {"id": 990, "name": "Пастеризация", "image": null}
  ]
```

- `image` — JSON-объект из `image` состояния по умолчанию компонента-проекта, как есть.
- `null` — у проекта ещё нет `image` (состояния нет или его не записывали).
- Поле `image` должно присутствовать **всегда** (хотя бы `null`): по его отсутствию фронт понимает,
  что бэк ещё старый, и остаётся на localStorage.

## 2. Запись — новая ручка

```
PUT /api/editor/projects/{projectId}/image
{"image": { ... }}
→ 200 {"image": { ... }}      // то, что теперь хранится
```

| | |
|---|---|
| Хранение | В `image` состояния по умолчанию компонента-проекта. Состояния нет — создать. Содержимое бэкенд **не разбирает и не проверяет**: формат принадлежит фронту. |
| Запись | Объект целиком заменяет хранимый, последняя запись побеждает. Фронт перед записью перечитывает `image` и меняет только свой ключ — чужие не теряются. |
| Версии | **Не создавать**: ни версию документа, ни выпуск, не менять версии сцен. Это настройка рабочего места, а не правка схемы — иначе закрепление вкладки плодило бы выпуски и конфликты сохранения. |
| Выпуски | В снимок выпуска не входит, `TREE_CHANGED` не вызывает. |
| Ошибки | 404 — проекта нет; 400 — `image` не объект. |
| Доступ | Список проектов читают и редактор, и монитор (через gateway). Пишет только редактор. `X-Username` проставляет gateway. |

## Что лежит в `image` (для сведения)

```json
{
  "pinnedScenes": { "v": 1, "ids": [12, 7, 30], "recipesIndex": 3 }
}
```

- `ids` — закреплённые схемы в порядке вкладок; имена фронт берёт из списка схем. Id удалённой
  схемы (или схемы, которой нет в prod-выпуске) просто не показывается — чистить на бэке не нужно.
- `recipesIndex` — место вкладки «Рецепты» среди закреплённых.
- `v` — версия формата.
- Менять закрепления фронт позволяет только в редакторе; монитор их только читает.

## Пока этого нет

В списке проектов нет поля `image`, а `PUT …/image` отвечает 404/405 — фронт молча остаётся на
localStorage, как сейчас. Когда появится, первый инженер, открывший проект в редакторе, перенесёт
свои локальные закрепления в `image`, если там ещё нет `pinnedScenes`.
