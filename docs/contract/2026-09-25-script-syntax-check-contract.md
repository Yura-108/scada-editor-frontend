# Проверка синтаксиса скриптов при сохранении — что меняется для фронта

Дата: 25.09.2026. Задача бэкенда `scada-8fw` — сделано.
Подробности на стороне бэка — `docs/modules/editor.md`, «Четыре вида логики».

В конце файла — второй раздел: [номер версии сцены после правки свойства](#номер-версии-сцены-после-правки-свойства-scada-r9lr)
(`scada-r9lr`), тоже про эндпоинты свойств.

## Что изменилось

Сохранение сцены и правка свойства теперь отклоняются, если в каком-нибудь скрипте синтаксическая
ошибка. Раньше битый скрипт сохранялся и падал только при исполнении — у оператора.

Проверяются:

| Поле | Эндпоинты |
|---|---|
| `scripts[].script` | `POST` / `PUT /api/editor/components` |
| `events[].script` | те же |
| `bindings[].script` → поле `code` внутри JSON | те же |
| `properties[].onChange` | те же, плюс `POST` / `PUT /api/editor/properties` |

Скрипт проверяется как **тело функции**, как вы его и исполняете (`new Function(…, code)`):
`return` на верхнем уровне допустим. Пустой скрипт допустим. Восстановление версии не проверяется.

## Ответ при ошибке

`400`, в теле обычная форма ошибки editor:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Script syntax error in script 'Открыть' of component 'Насос' at line 3: SyntaxError: …",
  "timestamp": "…"
}
```

В `message` — вид скрипта (`script`, `event`, `binding`, `on_change of property`), его имя (у события —
тип события), имя компонента и строка в тексте пользователя. Сохраняется всё или ничего: при `400`
в базу не записано ни одного компонента.

## Что сделать на фронте

1. **Показывать `message` при `400` сохранения сцены**, а не общее «не удалось сохранить», —
   иначе автор не найдёт, какой скрипт чинить среди сотен в сцене. Если обработчик уже выводит
   `message` бэкенда, правка не нужна — проверьте.
2. **Автосохранение**: `400` синтаксиса будет повторяться на каждом такте, пока скрипт не исправят.
   Стоит показывать ошибку один раз, а не тостом на каждое автосохранение.
3. Необязательно: проверять синтаксис в редакторе скрипта до сохранения (`new Function(code)` в
   `try`) — бэкенд всё равно проверит, но автор увидит ошибку сразу.

На 25.09.2026 все скрипты в базе стенда корректны, так что существующие сцены сохраняются как раньше.

# Номер версии сцены после правки свойства (`scada-r9lr`)

Бэкенд готов с 18.09.2026 (`scada-6e1`), **ждёт фронт**. Основание — §8
[2026-08-11-frontend-contract-changes.md](2026-08-11-frontend-contract-changes.md).

## Что отдаёт бэкенд

Каждая правка свойства записывает новую версию сцены и возвращает её номер:

| Запрос | Где номер в ответе |
|---|---|
| `POST /api/editor/properties` | `version_no` в теле свойства |
| `PUT /api/editor/properties/{id}` | `version_no` в теле свойства |
| `DELETE /api/editor/properties/{id}?based_on_version=N` | тело `{"version_no": 51}` |

```json
{ "id": 3886, "name": "ST", "component_id": 8812, "tag_id": "…", "version_no": 51 }
```

Если содержимое сцены не изменилось, новой версии нет — приходит прежний номер. Поэтому номер
нужно брать из ответа, а не считать как «прошлый + 1».

## Что сломано сейчас

Единственный такой вызов на фронте — переименование свойства:
`renamePropertyOnServer` в `src/store/useEditorStore.ts`, через прокси
`src/app/api/editor/tags/[id]/route.ts` (он отдаёт тело бэкенда как есть). Функция возвращает
`true` и выбрасывает тело ответа, `sceneVersion` в сторе остаётся прежним. После переименования
сцена уже на версии N+1, а фронт считает, что на N:

- ручное сохранение уходит с `based_on_version = N` и проходит через слияние (§2 основного
  контракта) — лишняя работа сервера и риск ложного конфликта;
- **автосохранение получает `409`** — оно не сливает, отвечает `version_mismatch`.

## Что сделать на фронте

1. В `renamePropertyOnServer` прочитать тело ответа и вернуть `version_no` (при отказе сервера —
   по-прежнему `false`).
2. В месте вызова (действие стора `editProperty`, ветка переименования), если номер пришёл, записать его в
   `sceneVersion` стора **до** локального применения нового имени.
3. `POST`/`DELETE` свойств фронт сейчас не вызывает — свойства уходят вместе со сценой. Если такие
   вызовы появятся, правило то же: `version_no` из ответа → `sceneVersion`.

## Как проверить

Открыть сохранённую сцену, переименовать свойство у компонента и дождаться автосохранения
(или сохранить вручную): ответа `409` и плашки «сцену сохранил другой пользователь» быть не должно,
а номер версии на панели инструментов — вырасти на один после переименования.
