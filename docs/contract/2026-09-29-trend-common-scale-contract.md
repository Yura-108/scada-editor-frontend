# Тренд: общая шкала Y и коэффициент пера — контракт для фронта

Дата: 29.09.2026. Задача в beads — см. «Тренд: общая шкала Y и коэффициент пера». Меняет
раздел 1 `2026-09-28-tag-archive-contract.md` (оформление тренда). **Бэкенд не меняется**:
`trend` лежит в `image` базового состояния непрозрачным JSON, архив (`GET
/api/runtime/archive/values`) и живые `UPDATE.tags` по-прежнему отдают **сырые** значения тега.

## Зачем

Сейчас у каждого пера свои `min`/`max`, линия вписывается в них на всю высоту графика, а подписи
оси Y берутся у одного пера (первого с данными). На тренде танка ось подписана 0…110 (по
температуре), и масса 27 500 кг «читается» по оси как 27,5 — число на оси к массе отношения не
имеет. Оператору нужна одна честная ось: общие `min`/`max` на весь тренд, а разные единицы
приводятся к ней коэффициентом пера (масса ×0,001 → тонны).

## Новый формат `trend`

```json
"trend": {
  "window": 1800,
  "step": 300,
  "min": 0,
  "max": 110,
  "pens": {
    "pen1": { "color": "#ef4444", "width": 2 },
    "pen2": { "color": "#3b82f6", "width": 2, "k": 0.001 }
  }
}
```

| Поле | Смысл |
|---|---|
| `min` / `max` | **общая** шкала Y всего тренда. Не заданы (оба или одно) — авто по данным всех перьев **после** умножения на `k` |
| `pens.<name>.k` | коэффициент пера: на график, ось, подсказку и легенду идёт `value × k`. Нет, `0`, не число — `1` |
| `pens.<name>.color` / `width` | без изменений |
| `pens.<name>.min` / `max` | **больше не используются**: читать не надо, при сохранении не писать |

Единица в подписи — в `label` свойства пера («Масса, т»), отдельного поля нет. Bool/integer перья
по-прежнему ступенькой, `k` к ним тоже применяется.

## Что поменять во фронте

| Где | Что |
|---|---|
| `types/editorElement.type.ts` | `TrendSettings`: `min?`, `max?`; `TrendPenStyle`: `k?`, убрать `min`/`max` |
| `lib/editor/trendSettings.ts` | `readTrendSettings` — читать `min`/`max` тренда; `readPen` — `k` (конечное, ≠ 0, иначе не класть), `min`/`max` пера не читать |
| `lib/editor/trendGeometry.ts` | значения точек × `k` пера; **один** `yOf` на все перья по общей шкале (заданной или авто по всем перьям); `yTicks` — по общей шкале, без цвета пера (`yScaleColor` не нужен); `last` — уже × `k` |
| `components/editor/TrendSettingsBlock.tsx` | поля «Шкала Y: мин / макс» на уровне тренда; у пера вместо мин/макс — «Коэффициент» (по умолчанию 1) |
| `components/monitor/TrendModal.tsx` | переопределение масштаба оператором — одна пара мин/макс на тренд, а не на перо (`scaleOverride` → `{min?, max?}`); подсказка и легенда показывают `value × k` |
| `components/editor/canvas/shapes/TrendShapeElement.tsx` | превью в редакторе — те же правила |

## Старые данные

У существующих трендов (4 сцены «Продукция» проекта «Нормализация») сейчас `pens.*.min/max` и нет
общих `min`/`max`. После выкладки фронта они покажутся с авто-шкалой по всем перьям — это ожидаемо.
Проставить `min`/`max` и `k` в этих сценах сделает бэк скриптом через `PUT /api/editor/components`
(как правку сцены), когда фронт будет готов, — сказать, какие значения нужны.
