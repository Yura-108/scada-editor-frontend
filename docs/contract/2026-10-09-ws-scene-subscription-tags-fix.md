# SUBSCRIBE_SCENE: в `tags` — только теги вне сцены

Дата: 09.10.2026. Уточнение к `2026-10-08-ws-scene-subscription-contract.md`.
Бэкенд: задача scada-d1t6, ветка `dev` (подписка на сцену — коммит `aa84407`, запушен 09.10.2026).
Фронт: коммит `0f547bc` (`origin/nextjs`), `useRuntimeEngine.ts`.

## Что не так

Фронт кладёт в `SUBSCRIBE_SCENE.tags` все теги открытой схемы и объясняет это так: прямые привязки
«элемент ← тег» не являются свойствами, и runtime может не найти их в поддереве сцены.

На деле runtime их находит. Набор тегов сцены (`TagSubscriptionIndex`) собирается из:

- `properties[].tag_id` всех компонентов поддерева сцены (объекты, их дети);
- примитивов групп из `state.image.composition`: их `properties[].tag_id` и `bindings[]` с
  `direct: true` и `tag`.

То есть сцена уже покрывает `elementKeysByTagId`, `tableCellsByTagId`, `directTagsByTagId` и
теги-триггеры биндингов: все они берутся из свойств и прямых привязок элементов сцены.

Чем грозит: подписанные на одну сцену без `tags` делят один кадр `UPDATE`, и он сериализуется
один раз на всех. С непустым `tags` у каждой сессии свой набор тегов, кадр собирается на каждую
сессию отдельно. Трафик всё равно режется, а экономия CPU runtime, ради которой подписку вводили,
почти пропадает.

## Что сделать во фронте

В `tags` отправлять только `useRuntimeTagInterest()`, то есть теги панелей вне сцены (инспектор и
т.п.). Без открытых панелей поле `tags` не отправлять совсем:

```json
{"type": "SUBSCRIBE_SCENE", "sceneId": 10556}
```

Локальное сравнение «изменилась ли подписка» и сброс значений выпавших тегов можно оставить на
полном наборе тегов схемы, это внутреннее дело фронта. Меняется только то, что уходит в сокет.

## Что делает бэкенд (страховка)

С 09.10.2026 runtime выкидывает из `tags` теги, которые уже есть в сцене (ветка `dev`). Если ничего не осталось,
сессия получит общий набор тегов сцены. Значит, старый фронт тоже заработает правильно, но лишние
килобайты в каждом `SUBSCRIBE_SCENE` уходить продолжат.

Если на экране тег сцены замер или висит «нет данных», а фронт его в `tags` не прислал, это ошибка
индекса runtime, а не фронта: присылайте `sceneId` и путь тега.
