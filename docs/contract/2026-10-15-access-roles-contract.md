# Роли и уровни доступа — контракт для фронта

> 15.10.2026, бэк — ветка `feat/access-roles` (scada-ld5m). Фронт делает сам; правила на бэке уже
> проверяются, этот документ — что поменялось на проводе и что фронту показать.

## Что изменилось коротко

- **Регистрации нет.** `POST /api/auth/register` удалён, через gateway — `401`. Страницу `/register`
  убрать; пользователей заводит администратор в админке.
- **Права по проектам.** У пользователя в каждом проекте — галочки `view` (просмотр), `operate`
  (действия в мониторе), `edit` (правка в редакторе) и уровень 1–10 (только с `operate`).
  Администратор — отдельный флаг, ему можно всё, уровень 10.
- **Бэк отказывает сам**, фронт только прячет недоступное. Любое скрытие на фронте — удобство, не защита.

## Токен

В JWT добавлен claim `admin` (boolean) — по нему показывать пункт «Администрирование». Остальные
права из токена не брать: они меняются без перевыпуска токена.

```json
{ "sub": "ivanov", "userId": 1528, "admin": false, "iat": 1792063526, "exp": 1792149926 }
```

## Мои права

`GET /api/auth/me/access`:

```json
{
  "admin": false,
  "projects": {
    "10554": { "view": false, "operate": true, "edit": false, "level": 3 },
    "8501":  { "view": true,  "operate": false, "edit": true,  "level": null }
  }
}
```

То же — в списке проектов: `GET /api/editor/components/projects` отдаёт **только** проекты, где у
пользователя есть хоть одна галочка, и у каждого поле `access`:

```json
[{ "id": 10554, "name": "Нормализация", "image": {…},
   "access": { "view": false, "operate": true, "edit": false, "level": 3 } }]
```

Что показывать:

| Права | Монитор | Редактор |
|---|---|---|
| только `operate` | смотреть, нажимать кнопки в пределах уровня | проект не открывается (`403`) — в списке редактора не показывать |
| только `view` | смотреть, кнопки неактивны | открыть, «потыкать» локально, **сохранение, выпуск, prod — скрыть** |
| `edit` | смотреть, кнопки неактивны | всё |
| `operate` + `edit` | всё в пределах уровня | всё |

## Уровни действий

- **Кнопка (ACTION)** разрешена, если `level` пользователя ≥ `access_level` скрипта (`null` = 1).
  Кнопку со скриптом выше уровня — делать неактивной.
- **«Опции» и инспектор объекта** (`POST /api/runtime/tags/write`, `…/properties/write`) — уровень
  **≥ 9**. Ниже — пункт меню не показывать. В `tags/write` поле `projectId` теперь **обязательно**
  (без него `400`), и писать можно только теги этого проекта (иначе `403 PATH_NOT_ALLOWED`).
- **Операции процедуры** (`start`, `confirm`, `pause`, `resume`, `jump`, `abort`) — уровень из
  таблицы проекта (ниже); нет значения — 1.

Уровни берутся из **prod-выпуска**: у скрипта в дереве выпуска поле `access_level`, в корне выпуска —
`procedure_levels`. Поменял уровень в редакторе — до монитора он доедет только с новым выпуском и prod.

## Редактор: где задаются уровни

**Скрипт** — новое поле `access_level` (1–10 или `null`) в `scripts[]` компонента, при сохранении и
в ответе. Вне 1…10 — `400`. Показать в окне скрипта полем «Уровень доступа».

```json
"scripts": [{ "name": "Сброс аварии", "script": "…", "displayed": false, "access_level": 5 }]
```

**Скрипт шаблона** — то же поле в `scripts[]` шаблона (`/api/editor/templates`).

**ОБЯЗАТЕЛЬНО: перенос уровня при вставке шаблона.** Вставка шаблона — копия на фронте
(`instantiateTemplate`, `src/lib/editor/templateInstance.ts`). Если не перенести `access_level`,
у вставленного скрипта уровень молча станет 1 — бэк этого не видит и не поймает:

```ts
scripts: template.scripts.map((s) => ({
  name: s.name, script: s.script, displayed: s.displayed,
  access_level: s.access_level,          // без этого уровень станет 1
})),
```

**Таблица уровней процедур проекта** — в настройках проекта:

```
GET /api/editor/projects/{projectId}/procedure-levels      (view или edit)
PUT /api/editor/projects/{projectId}/procedure-levels      (edit)
{ "start": 5, "confirm": null, "pause": 2, "resume": null, "jump": 8, "abort": 2 }
```

`null` — уровень 1; вне 1…10 — `400`.

## Отказы

REST — во всех сервисах одинаково:

```json
403 { "error": "FORBIDDEN", "reason": "LEVEL_TOO_LOW", "requiredLevel": 9 }
```

| `reason` | Показать |
|---|---|
| `NO_PROJECT_ACCESS` | «Нет доступа к проекту» |
| `NO_OPERATE` | «Нет права управления» |
| `NO_EDIT` | «Только просмотр — сохранение недоступно» |
| `LEVEL_TOO_LOW` | «Нужен уровень доступа N» (`requiredLevel`) |
| `PATH_NOT_ALLOWED` | «Нет доступа к этой ветке базы каналов» |
| `NOT_ADMIN` | «Только для администратора» |
| `USER_DISABLED` | «Учётная запись отключена» → на страницу входа |
| `ACCESS_NOT_READY` | «Сервер запускается, повторите через несколько секунд» |

`401` (тело `reason: NO_USER` или пустое от gateway) — на страницу входа, как сейчас.

**WebSocket монитора:**

- Отказ в нажатии — сообщение, соединение живо:
  ```json
  { "type": "ACTION_DENIED", "scriptId": 512, "reason": "LEVEL_TOO_LOW", "requiredLevel": 5 }
  ```
  Показать всплывающее сообщение у кнопки, состояние не менять.
- Права отозваны или учётка отключена — сервер закрывает соединение кодом **`4403`**
  (причина `NO_PROJECT_ACCESS`). **Не переподключаться**: показать «Доступ к проекту отозван» и
  вернуть на список проектов. Обычный реконнект — только для прочих кодов.
- Подключение к чужой сессии — код `1008`.

## Админка (только `admin`)

| Действие | Запрос |
|---|---|
| Пользователи | `GET /api/auth/admin/users` → `[{id, login, admin, enabled}]` |
| Создать | `POST /api/auth/admin/users {login (3–50), password (6–100), admin}`; занятый логин — `409` |
| Включить / отключить, администратор | `PUT /api/auth/admin/users/{id} {enabled, admin}` |
| Сбросить пароль | `PUT /api/auth/admin/users/{id}/password {password}` |
| Удалить | `DELETE /api/auth/admin/users/{id}` |
| Права в проекте | `PUT /api/auth/admin/users/{id}/projects/{projectId} {view, operate, edit, level}`; все `false` — снять |
| Ветки каталога проекта | `GET` / `PUT /api/auth/admin/projects/{projectId}/branches` — `["Барановичи-1.BN1_MCA1"]` |
| Перепубликовать права | `POST /api/auth/admin/resync` (кнопка «Обновить права на сервисах») |

Последнего администратора нельзя отключить, разжаловать или удалить — `409`, показать текст из `message`.

Ветки каталога определяют, какие узлы базы каналов видит и правит пользователь проекта: `edit` в
проекте — правка узлов под ветками, `view` — чтение. Без веток каталог для него пуст.

Создавать проект может только администратор (`POST /api/editor/components/project`, как и компонент
`type: project` в `POST /components`, иначе — `403 NOT_ADMIN`): кнопку «Новый проект» показывать
только ему. Удалить корень ветки каталога (и узлы выше) и импортированный проект — тоже только
администратор.

## Свой пароль

`PUT /api/auth/me/password {oldPassword, newPassword}` → `204`; неверный текущий — `400`.

## Рецепты — временно

Пока рецепты глобальные (этап 2 привяжет их к проекту и выпуску): читать может любой вошедший,
менять — тот, у кого `edit` хотя бы в одном проекте.

## Уточнения (15.10.2026, сверено с кодом бэкенда, `dev` до 05c8c9e)

- **Уровни процедур в мониторе** — `GET /api/runtime/projects/{projectId}/procedure-levels`
  (c496d86): все шесть операций, `null` = 1, из prod-выпуска; доступен всем, кто видит монитор,
  включая оператора с одним «управлением». 409 — проект не в эксплуатации. Перечитывать при
  `TREE_CHANGED`. Editor-эндпоинт `/api/editor/projects/{id}/procedure-levels` — черновик.
- **Права пользователя для админки** — `GET /api/auth/admin/users/{id}/projects` (216acdc) →
  `{"<projectId>": {view, operate, edit, level}}`; проекта нет в ответе — прав нет. 404 — нет
  пользователя.
- **Коды закрытия WS** (05c8c9e): `4403` — права отозваны / учётка отключена, не переподключаться;
  `1013` — сервер после рестарта ещё не загрузил права, переподключиться через 3–5 с; `1008` —
  чужая сессия, не переподключаться; прочие (в т. ч. `1003`, `1001`) — как раньше.
- `ACCESS_NOT_READY` приходит **403**: повторить через несколько секунд, это не отказ.
- `/me/access` у администратора может прийти с пустым `projects` — `admin: true` значит «всё,
  уровень 10». В списке проектов админ получает полный `access`.
- `ACTION_DENIED.requiredLevel` бывает `null` (у `NO_OPERATE` / `NO_PROJECT_ACCESS`).
- `tags/write` и `properties/write`: нужны `operate` **и** уровень ≥ 9 (порог настраивается на
  сервере, `RUNTIME_DIRECT_WRITE_LEVEL`). Проект не в эксплуатации — все теги `PATH_NOT_ALLOWED`.
- `POST /admin/users` отвечает **200** с `UserDto`; `PUT /admin/users/{id}` требует **оба** поля
  `{enabled, admin}`; ошибки auth — `{message}`. Новый пароль — 6–100 символов (иначе 400).
- `PUT …/procedure-levels` отвечает 200 с сохранённым набором и заменяет все шесть полей.
- База каналов: `projectId` не нужен — права объединяются по веткам всех проектов пользователя;
  чтение без прав возвращает отфильтрованные данные (пустое дерево), а не 403.
- Шаблоны палитры (`/api/editor/templates`) может править любой вошедший.
