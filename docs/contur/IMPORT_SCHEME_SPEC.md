# Спецификация JSON-схем для импорта в редактор мнемосхем

Дата: 19.08.2026
Кому: разработчику, который формирует `*.json` со схемами (выгрузка CONTUR и любые другие
генераторы).
Что описывает: как должен быть устроен файл, чтобы схема легла в редактор без правок,
масштабировалась предсказуемо и **вставала ровно по клеткам**, а с элементами потом было
удобно работать руками.

Связанные документы: `INTEGRATION.md` (что отдаёт CONTUR), `CONTUR_IMPORT_PLAN.md` (как
устроен приём на нашей стороне). Здесь — требования к самому файлу.

---

## 0. Коротко: чек-лист на одну страницу

Единицы и полотно:

| Параметр | Значение |
|---|---|
| Единица длины | 1 = 1 пиксель холста |
| Начало координат | левый верхний угол, X вправо, Y вниз |
| Рабочее поле | размер листа сцены, см. §7a (прежнего «мира 5000×5000» не существует) |
| Шаг сетки | **20** (жёстко зашит в редакторе, не настраивается) |
| Узлы сетки | все координаты, кратные 20: `0, 20, 40, …` |
| Диапазон зума | 0.03 … 3.0 |

Правила, которые дают «ровно по клеткам»:

1. Все **объекты** (группы, рамки, кружки устройств, тексты, виджеты) — координаты и
   размеры **кратны 20**.
2. Все **размеры** — не меньше 20, на практике не меньше 40 (2 клетки).
3. У круга **центр** ставится в узел сетки, а `radius` кратен 20 (минимум 20 → Ø40).
4. У группы `x, y, w, h` кратны 20 — иначе локальная сетка детей уедет относительно
   мировой, и дети внутри группы будут «между клеток» навсегда.
5. У отрезка оба конца (`x1,y1` и `x2,y2`) — в узлах сетки, длина ≥ 20.
6. Никаких процентов (`"84.9%"`) и никаких дробных координат у объектов.
7. Один масштабный коэффициент на весь лист, применённый до округления к сетке (см. §2).

Почему это нельзя доделать на нашей стороне — §3. Это главный раздел документа.

## 1. Общая структура файла

Файл — **плоский JSON-массив** элементов (одиночный объект тоже принимается).
Вложенности в файле нет: иерархия задаётся ключами.

```json
[
  {"key": "grp_tank1", "type": "group",     "parentKey": "undefined", "children": ["frm_tank1", "dev_v1"]},
  {"key": "frm_tank1", "type": "rectangle", "parentKey": "grp_tank1", "children": []},
  {"key": "dev_v1",    "type": "circle",    "parentKey": "grp_tank1", "children": []}
]
```

Обязательные поля у каждого элемента:

| Поле | Тип | Смысл |
|---|---|---|
| `key` | string | уникальный в пределах файла идентификатор. При импорте заменяется на новый uuid, ссылки переписываются автоматически |
| `type` | string | тип элемента, см. §5 |
| `parentKey` | string | `key` родителя; у верхнеуровневых — `"undefined"`, `"null"` или отсутствует |
| `x`, `y` | number | позиция (смысл зависит от типа, см. §5) |
| `w`, `h` | number | габарит |

Дополнительно у контейнеров:

| Поле | Тип | Смысл |
|---|---|---|
| `children` | string[] | ключи детей, **в порядке отрисовки** |

**Связь родитель ↔ ребёнок обязана быть двусторонней**: у ребёнка `parentKey`, у родителя
этот ключ в `children`. Холст обходит детей по массиву `children`, поэтому ребёнок только
с `parentKey` не отрисуется вовсе. Импорт достраивает недостающую сторону и предупреждает
об этом в тосте — но полагаться на это не нужно.

Чего слать **не надо**:

| Поле | Почему |
|---|---|
| `id` | серверный идентификатор. Всегда `null` (или отсутствует) — иначе элемент притворится уже существующим на бэкенде |
| `composition` | у нас это массив ключей примитивов компонента. Если у вас это булево «контейнер ли» — просто не отправляйте, импорт его игнорирует |
| `isComponent` | ставится редактором по команде «Создать компонент» |
| `states` | можно не отправлять: импорт сам добавит единственное состояние «Нормальное». Если отправляете — см. §7 |

Всё остальное, чего нет в модели редактора (`lua_name`, `pdf_name`, `tech_object`,
`device_type`, `article`, `descr`, `line_id`, `confidence`, …), **копируется как есть и
переживает цикл «сохранили → загрузили»**: сериализатор запекает неизвестные поля в
служебный блоб и разворачивает обратно. Метаданные можно слать свободно.

## 2. Масштаб: как перевести чертёж в пиксели холста

Масштабировать нужно **один раз, единым коэффициентом на весь лист**, до округления
координат к сетке. Коэффициент подбирается так, чтобы самый мелкий значимый символ занял
целое число клеток:

```
k = 40 / d      где d — типовой размер символа устройства в исходных единицах
```

40 = две клетки — минимальный размер, при котором объект остаётся кликабельным и
редактируемым (см. §4).

Пример для листов CONTUR (единица — пункт PDF, символ устройства ≈ 33 пт, k = 40/33 ≈ 1.2):

| Лист | Исходный размер | После ×1.2 | Влезает в 5000×5000 |
|---|---|---|---|
| A0 | 3368 × 2384 | 4042 × 2861 | да |
| A1 | 2392 × 1695 | 2870 × 2034 | да |

**Раздел устарел с 01.09.2026.** Коэффициент больше не подбирается под холст: по
договорённости фигура устройства равна **200 единицам** (`k = 200 / d`, где `d` — типовой
символ листа в пунктах), а размер листа приезжает отдельно, в `meta.canvas` (§7a).
Проверка «влезает в 5000×5000» **отменена** — координаты ничем не ограничены. Всё
остальное в этом разделе (единый коэффициент на лист, сдвиг в начало координат,
округление к сетке после масштабирования) остаётся в силе.

Дополнительно:

- **Сдвиньте чертёж в начало координат.** После масштабирования вычтите минимальные X и Y,
  чтобы габарит листа начинался в `(0, 0)`. Начальная камера редактора стоит в `(0, 0)` при
  зуме 1 — схема, начинающаяся с `x = 1740`, откроется пустым экраном. Смещение тоже
  кратно 20.
- **Отрицательные координаты не запрещены, но нежелательны** — уводят содержимое за
  видимую при открытии область.
- **Проценты (`"84.9%"`) не использовать.** Теперь они считаются от размера листа
  (§7a), но если служебного элемента в файле нет — по-прежнему от 5000 по обеим осям,
  а лист не квадратный: A0 растянуло бы с 1.41:1 до 1:1.
- Если у чертежа есть выраженный шаг (расстояние между нитками трубопровода, шаг колонок),
  подберите `k` так, чтобы этот шаг стал кратен 20 — тогда на сетку сядет не только
  оборудование, но и сам чертёж.

## 3. Сетка 20 и почему выравнивать надо на источнике

Шаг сетки — **20**, функция привязки `snap(v) = round(v / 20) * 20`. Значение зашито в коде
(`src/lib/utils.ts`), пользователь его не меняет. Линии сетки проходят ровно по координатам,
кратным 20.

Редактор привязывает к сетке **только то, что двигает пользователь**, и делает это
по-разному для двух групп типов. Это и есть источник «кривых» схем после импорта.

| Группа типов | Что происходит при перетаскивании |
|---|---|
| `rectangle`, `text`, `group`, `image`, все виджеты (`button`, `table`, `gauge`, …) | новая позиция = `snap(x)`, `snap(y)` — **абсолютная привязка**. Элемент, стоявший на `x = 137`, при первом же сдвиге прыгает на `140` |
| `circle`, `line`, `polygon` | к сетке привязывается **смещение**, а не позиция: элемент едет строго на целое число клеток, исходный сдвиг относительно сетки сохраняется навсегда |

Отсюда два следствия, которые невозможно исправить в редакторе:

1. Если объект приехал не на узле сетки, **он не встанет на сетку сам**. Круг и отрезок так
   и останутся смещёнными на свои `+7.3 px` относительно всего остального; выровнять их
   можно только вручную, поштучно, через панель «Геометрия».
2. Прямоугольники и тексты, наоборот, **дёргаются при первом касании** — схема, выглядевшая
   ровной, начинает разъезжаться по мере редактирования: сдвинутые элементы уже на сетке,
   несдвинутые ещё нет.

Поэтому координаты должны быть кратны 20 **в самом файле**. Ничего другого не требуется:
импорт координаты намеренно не трогает (чертёж должен ложиться точка в точку).

### 3.1 Два уровня строгости

Требовать кратности 20 от каждого отрезка перерисованного PDF нельзя — диагонали и кривые
заметно деформируются. Разделите содержимое.

**Уровень A — обязательно на сетке.** Всё, что пользователь будет двигать, выделять и
выравнивать:

- группы (техобъекты) — `x, y, w, h`;
- рамки (`rectangle`) — `x, y, w, h`;
- устройства (`circle`) — центр в узле, `radius` кратен 20;
- тексты — `x, y`;
- любые виджеты.

**Уровень B — чертёж (линии из PDF).** Здесь допустимы точные координаты, но:

- ортогональные сегменты (|dx| < 1 или |dy| < 1) — привязывайте оба конца к узлам сетки,
  если это смещает точку не больше чем на 10 (полклетки). Так трубопроводы садятся на сетку,
  а геометрия не ломается;
- диагонали и разложенные кривые — оставляйте как есть;
- сегменты короче 20 после масштабирования — склеивайте с соседними (§9) либо удаляйте.

### 3.2 Локальные координаты и сетка внутри групп

Координаты детей отсчитываются от левого верхнего угла родителя. Привязка при
перетаскивании тоже считается **в координатах родителя**.

Значит, `snap()` внутри группы совпадёт с мировой сеткой **только если начало группы само
кратно 20**. Группа с `x = 1053` делает всю свою внутренность неисправимо смещённой на
13 px: визуально дети стоят между клеток, а редактор считает их выровненными.

> Правило: `group.x % 20 === 0 && group.y % 20 === 0` — обязательно.
> Тогда ребёнку достаточно, чтобы его локальные `x, y` были кратны 20.

## 4. Минимальные и рекомендуемые размеры

Жёсткие ограничения редактора:

| Ограничение | Значение | Где срабатывает |
|---|---|---|
| Минимальные `w` / `h` | **20** | любое изменение размера обрезается до 20 — элемент 8×8 при первом ресайзе станет 20×20 |
| Минимальный `radius` круга | **20** | ручка ресайза круга привязывает радиус к сетке, минимум — одна клетка |
| Минимальная толщина линии | **0.5** | значения меньше поднимаются до 0.5 при импорте выгрузки CONTUR |

Рекомендации (не проверяются автоматически, но определяют удобство работы):

| Что | Минимум | Рекомендуется |
|---|---|---|
| Кружок устройства | `radius` 20 (Ø40) | `radius` 20 или 40, центр в узле сетки |
| Рамка техобъекта / прямоугольник | 40 × 40 | кратно 20 по обеим сторонам |
| Длина отрезка | 20 | кратно 20 для ортогональных |
| Кегль текста (`fontSize`) | 10 | **12** — подписи, **16** — имена техобъектов |
| Толщина линии (`strokeWidth`) | 0.5 | 1 — чертёж, 2 — трубопровод, 3 — акцент |
| Зазор между соседними объектами | 20 | 20 или 40 |

Про кегль отдельно. Присылаемые сейчас 8 pt подписей и 10 pt имён контуров рассчитаны на
печатный лист. На экране при зуме «весь лист» (0.2…0.35) это 2–3 px — нечитаемо, и человек
вынужден работать на зуме 1.5+, где в окно влезает угол схемы. После масштабирования по §2
(k ≈ 1.2) 8 pt превращаются в 9.6 px — этого мало. Задавайте кегль сразу в целевых
пикселях: 12 и 16.

Про толщину линий. `stroke_width` из PDF (медиана 0.71, минимум 0.057) при зуме «весь лист»
уходит в 0.2 px, и чертёж бледнеет до нечитаемости. Импорт поднимает всё, что ниже 0.5, но
лучше квантовать на своей стороне в три ступени 1 / 2 / 3: чертёж станет контрастнее, а файл
сожмётся лучше.

## 5. Типы элементов и их поля

Ниже — **имена полей, которые читает рендер редактора**. Если вы шлёте выгрузку в диалекте
CONTUR (`stroke_width`, `font_size`, `borderColor`), см. §6: они переименовываются на нашей
стороне автоматически, и менять формат не требуется.

Общие поля, работающие у всех типов: `rotate` (градусы), `opacity` (0…1), `visible`,
`label`, `bg` (заливка).

### 5.1 `line` — отрезок

Основной элемент перерисованного чертежа.

| Поле | Тип | Смысл |
|---|---|---|
| `x1, y1, x2, y2` | number | **концы отрезка — это и есть геометрия**, рисуется по ним |
| `x, y` | number | середина отрезка (для рендера не используется, но нужна для группировки и выделения) |
| `w, h` | number | габарит отрезка |
| `strokeColor` | string | цвет линии (`#e53935`) |
| `strokeWidth` | number | толщина, ≥ 0.5 |
| `strokeDasharray` | string | пунктир: `"6 4"`, пусто — сплошная |
| `arrowStart`, `arrowEnd` | boolean | наконечники стрелки |

Сетка: **оба конца в узлах сетки**. Концы отрезка перетаскиваются ручками, и каждая ручка
привязывается к сетке независимо — у отрезка короче 20 обе ручки могут схлопнуться в один
узел, и отрезок исчезнет.

### 5.2 `circle` — круг (маркер устройства)

| Поле | Тип | Смысл |
|---|---|---|
| `x, y` | number | **левый верхний угол габарита** (не центр!), центр = `x + radius` |
| `radius` | number | радиус; кратен 20, минимум 20 |
| `w, h` | number | **обязательно `2 × radius`** — по ним считаются выделение, рамка группы и «вписать в экран» |
| `color` или `bg` | string | заливка |
| `strokeColor`, `strokeWidth` | | обводка |

Про начало координат: в выгрузке CONTUR `x, y` — **центр**, и вычитание радиуса делает
нормализатор на нашей стороне (§6). Если вы формируете файл в нативном формате редактора —
кладите сразу левый верхний угол.

Сетка: удобнее всего, когда **центр** попадает в узел, а `radius` кратен 20 — тогда и угол
габарита `(центр − radius)` тоже оказывается в узле. Перетаскивание круга привязывает к
сетке именно центр.

### 5.3 `rectangle` — прямоугольник, рамка, подложка

| Поле | Тип | Смысл |
|---|---|---|
| `x, y` | number | левый верхний угол |
| `w, h` | number | размер, кратно 20 |
| `color` или `bg` | string | заливка; `"transparent"` — допустимое значение |
| `strokeColor`, `strokeWidth` | | обводка |
| `strokeDasharray` | string | пунктир, например `"6 4"` |
| `rx` | number | скругление углов |
| `label` | string | подпись **по центру фигуры**; если рядом уже есть отдельный `text`, оставляйте пустым, иначе надпись задвоится |
| `textColor` | string | цвет `label` |

### 5.4 `text` — строка

| Поле | Тип | Смысл |
|---|---|---|
| `x, y` | number | **левый верхний угол первой строки** |
| `text` | string | содержимое (читается именно `text`, `label` для текста не используется) |
| `fontSize` | number | кегль в пикселях, рекомендуется 12 / 16 |
| `fontFamily` | string | по умолчанию `Arial` |
| `bold` | boolean | полужирный |
| `color` (или `textColor`) | string | цвет строки; `color` имеет приоритет |
| `align` | string | `left` / `center` / `right` — работает только при фиксированной ширине |
| `autoWidth` | boolean | `true`/не указано — ширина по содержимому, перенос только по `\n`; `false` + `w` — фиксированная ширина с переносом по словам |
| `w, h` | number | габарит; **проставляйте его**: по нему считаются рамка группы, выделение прямоугольником и «вписать в экран». `w = h = 0` означает для этих операций точку |

Оценка габарита при `autoWidth`: `h ≈ fontSize × 1.2`, `w ≈ 0.55 × fontSize × число символов`
(Arial). Достаточно округлить вверх до кратного 20.

### 5.5 `group` — техобъект, контейнер

| Поле | Тип | Смысл |
|---|---|---|
| `x, y` | number | левый верхний угол, **кратно 20** (§3.2) |
| `w, h` | number | габарит рамки, кратно 20 |
| `children` | string[] | ключи детей в порядке отрисовки |

Важно: **группа сама по себе ничего не рисует.** Поля `bg`, `borderColor`, `borderStyle` в
модели есть, но рендер невыделенной группы прозрачен — она видна только когда выделена.
Видимая рамка техобъекта должна быть отдельным элементом `rectangle` **первым в `children`**
(локальные `x = 0, y = 0`, `w/h` — размер группы). Для диалекта CONTUR этот прямоугольник
создаёт нормализатор автоматически (§6); в нативном формате его создаёте вы.

Второй эффект того же прямоугольника: габарит группы пересчитывается по её детям (объединение
детских границ + отступ 40) при первом же перетаскивании ребёнка. Без прямоугольника,
держащего границу, рамка 997×782 схлопнется до скопления кружков.

### 5.6 `polygon` — многоугольник

| Поле | Тип | Смысл |
|---|---|---|
| `x, y` | number | начало локальной системы координат |
| `points` | number[] | `[x1,y1, x2,y2, …]` **относительно `x, y`**; допускается JSON-строка |
| `sides`, `radius` | number | если `points` нет или длина не равна `sides × 2`, фигура строится как правильный многоугольник в габарите `w × h` |
| `color`/`bg`, `strokeColor`, `strokeWidth` | | заливка и обводка |

Вершины перетаскиваются ручками с привязкой к сетке — держите координаты точек кратными 20.

### 5.7 Остальные типы

Полный список: `line`, `circle`, `rectangle`, `text`, `polygon`, `path`, `group`, `image`,
`progress_bar`, `checkbox`, `button`, `toggle`, `slider`, `dropdown`, `input`, `gauge`,
`table`, `trend`, `chart`, `custom`.

Это интерактивные виджеты редактора; для импортируемых чертежей они обычно не нужны.
Их размеры по умолчанию уже кратны 20 (кнопка 120×40, слайдер 160×20, таблица 300×160,
gauge 200×200) — держитесь этих величин, если всё-таки шлёте их.

**Неизвестный `type` не ломает импорт**: элемент рисуется прямоугольником `w × h` с
заливкой, обводкой и `label` по центру. Это удобный запасной вариант, но лучше указывать
`rectangle` явно.

## 6. Диалект CONTUR: что переименовывается автоматически

Файл считается выгрузкой CONTUR, если **хотя бы у одного элемента** есть поле
`stroke_width`, `contour`, `tech_object` или `lua_name`. Тогда включается нормализатор
(`src/lib/editor/conturImport.ts`):

| Из файла | Во что превращается |
|---|---|
| `stroke_width` | `strokeWidth`, но не меньше 0.5 |
| `font_size` | `fontSize` |
| `borderColor` у `line` и `circle` | `strokeColor` |
| `borderColor` у `text` | `textColor` (цвет самой строки) |
| `borderColor` у `group` | остаётся как есть |
| `color: "red" \| "blue"` | `contur_color` (смысловая метка сохраняется, но не становится заливкой) |
| `circle.x, y` (центр) | `x -= radius`, `y -= radius`, `w = h = 2·radius` |
| каждая `group` | добавляется дочерний `rectangle`-рамка первым в `children` |

Плюс: достраиваются односторонние связи `parentKey` ↔ `children`, а в тосте показывается
разбивка по типам (группы / линии / устройства / подписи / имена контуров / рамки) — по ней
делается приёмка.

> **Ловушка при смене формата.** Если вы перейдёте на нативные имена полей и уберёте
> `stroke_width` / `contour` / `tech_object` / `lua_name`, детектор не сработает и
> нормализатор не запустится. Тогда **вы обязаны сами**: (а) класть у круга левый верхний
> угол вместо центра, (б) добавлять `rectangle`-рамку в каждую группу. Иначе кружки уедут
> вправо-вниз на радиус, а рамки техобъектов станут невидимыми.
>
> Простейший способ остаться в известном режиме — оставить `tech_object` у групп: это и
> полезная метаданная, и маркер диалекта.

Отдельно про `color`: у нас это **заливка фигуры**, а не смысловая метка. Не используйте
`color` для классификации («труба», «контур устройства») — заведите своё поле
(`contur_color`, `semantic`, что угодно): неизвестные поля сохраняются без потерь.

## 7. Состояния, скрипты, привязки

Каждый элемент редактора имеет список состояний (`states`) — «Нормальное», «Авария» и т. п.
Импорт достраивает их сам, и в 99 % случаев **их не нужно отправлять**.

Если всё-таки отправляете:

```json
"states": [
  {"name": "Нормальное", "isDefault": true, "overrides": {}}
]
```

- ровно одно состояние с `isDefault: true`;
- `overrides` — объект с визуальными полями, перекрывающими базовые в этом состоянии;
  для импорта оставляйте пустым, иначе базовые `x/y/w/h` будут проигнорированы при отрисовке;
- `id` не указывайте (генерируется);
- если состояний несколько, **имена должны совпадать** у всех элементов одного техобъекта:
  переключение состояния распространяется по поддереву по имени.

Поля `scripts`, `bindings`, `properties`, `events` — пустые массивы или отсутствуют.
Привязки к тегам заводятся уже в редакторе, из файла они не приходят.

## 7a. Размер сцены (лист)

Сцена имеет конкретный размер, а не абстрактный «мир 5000×5000» (то число было
лишь протяжённостью отрисованной сетки и ничего не ограничивало).

**Размер редактор берёт из блока `canvas` служебного элемента** — того самого
`meta` с `visible: false`, который вы уже присылаете:

```json
"canvas": { "width": 11900, "height": 8400, "units": "px", "grid": 20 }
```

- `width`/`height` — размер листа **в единицах холста**, кратный сетке 20;
- остальные поля блока (`units`, `grid`, `scale`, `origin`) редактор не читает,
  но сохраняет без потерь — они ваши;
- блока или элемента нет — берётся пресет по умолчанию (A3, 11900 × 8400).

**Размер задаёт не формат бумаги, а плотность символов на листе.** По вашему
замеру 24 листов A3 один и тот же формат занимает от 7470 до 16200 единиц,
поэтому хранится именно число, а не «A3».

Лист — **подсказка, а не запрет**: рамка рисуется, но координаты ничем не
ограничены, и элементы за краем листа работают как обычно.

Проценты в координатах (`"x": "73.1%"`) считаются от этого же листа. Если
служебного элемента в файле нет — от прежних 5000, чтобы выгрузки прошлого
поколения импортировались как раньше.

## 8. Порядок отрисовки (z-order)

Порядок считается **среди соседей** (элементов с общим родителем), как в CSS: вложенный
элемент не может перекрыть чужого родителя. Внутри контейнера сортировка идёт по двум
ключам:

1. необязательное числовое поле `zIndex` — больше значит выше, отсутствует == `0`;
2. при равных `zIndex` — порядок массивов (сортировка стабильная):
   - элементы верхнего уровня — в порядке следования в файле;
   - состав группы — в порядке `composition` (примитивы), затем `children`.

**Для импорта ничего менять не нужно:** `zIndex` можно не присылать вовсе — тогда всё
определяет порядок массивов, ровно как раньше. Рекомендуемый порядок для чертежа:

1. подложки и рамки техобъектов (`rectangle`);
2. линии чертежа;
3. кружки устройств;
4. тексты.

То есть внутри группы `children` должен начинаться с рамки — она обязана оказаться под
устройствами, а не поверх них.

В редакторе `zIndex` правится числом в панели свойств («Слой (z-index)») и пунктами
контекстного меню «На передний план» / «На задний план»; он хранится в базе элемента и
уезжает на бэкенд внутри `states[].image`.

## 9. Объём файла и производительность

Контрольные цифры на текущих листах: A0 — 6076 элементов (4.8 МБ), A1 — 1129 (0.9 МБ).
Редактор их держит, но с оговорками:

- отсечение по видимой области включается от 200 корневых узлов; при зуме «весь лист»
  в кадре всё равно оказываются все элементы;
- при сохранении тело запроса несёт сцену **целиком**, вместе со служебными блобами: файл
  на 4.8 МБ на сервере становится больше.

Что даёт наибольший выигрыш, по убыванию:

1. **Склейка коллинеарных сегментов.** Кривые из PDF разложены на отрезки; соседние
   сегменты с одинаковым направлением, цветом и толщиной объединяются в один. На типовом
   листе это минус 30–50 % элементов без визуальной разницы.
2. **Отбрасывание сегментов короче 20** (менее одной клетки) — они всё равно нечитаемы и
   неперетаскиваемы.
3. **Квантование толщин** в 1 / 2 / 3 и цветов в короткую палитру.
4. **Округление координат.** После привязки к сетке дробей быть не должно вовсе; там, где
   точность нужна (диагонали), достаточно **двух знаков** после запятой.
5. Опция выгрузки только трубопроводов (`CONTUR_HMI_LINES=pipes`) — вдвое меньше элементов.

Ориентир: **до 3000 элементов на схему** — комфортно; 6000 — работает, но панорамирование
при полном зуме заметно тяжелее.

## 10. Самопроверка перед отправкой

Обязательные проверки:

- [ ] `key` уникальны в пределах файла;
- [ ] у каждого `parentKey` существует элемент с таким `key` (или это `"undefined"`);
- [ ] связь двусторонняя: `parentKey` ↔ `children`;
- [ ] `id` отсутствует или `null` у всех элементов;
- [ ] все координаты — числа, не строки, без `%`;
- [ ] габарит всей схемы влезает в `0…5000` по обеим осям;
- [ ] у всех групп `x, y, w, h` кратны 20;
- [ ] у всех `rectangle`, `text`, виджетов `x, y` кратны 20;
- [ ] у всех `circle`: `w = h = 2·radius`, `radius` кратен 20 и ≥ 20, центр в узле сетки;
- [ ] у всех `line`: длина ≥ 20; у ортогональных концы в узлах сетки;
- [ ] `w ≥ 20` и `h ≥ 20` у всего, кроме линий;
- [ ] `fontSize ≥ 12` у текстов;
- [ ] `strokeWidth ≥ 0.5`;
- [ ] в каждой группе первым ребёнком идёт `rectangle`-рамка (или в файле есть маркер
      диалекта CONTUR, и рамку добавит импорт).

Скрипт-валидатор (Node, без зависимостей):

```js
// node validate-scheme.js scheme.json
const fs = require("fs");
const GRID = 20;
const els = JSON.parse(fs.readFileSync(process.argv[2], "utf8"));
const byKey = new Map(els.map(e => [e.key, e]));
const onGrid = v => Number.isFinite(v) && v % GRID === 0;
const problems = [];
const add = (el, msg) => problems.push(`${el.type ?? "?"} ${el.key ?? "?"}: ${msg}`);

if (byKey.size !== els.length) problems.push("дублирующиеся key");

for (const el of els) {
  const t = String(el.type ?? "");
  if (el.id != null) add(el, "поле id должно быть null/отсутствовать");
  for (const k of ["x", "y", "w", "h"]) {
    if (typeof el[k] === "string") add(el, `${k} — строка, нужен number`);
  }
  const pk = el.parentKey;
  if (pk && pk !== "undefined" && pk !== "null") {
    const parent = byKey.get(pk);
    if (!parent) add(el, `parentKey ${pk} не найден`);
    else if (!(parent.children ?? []).includes(el.key)) add(el, "нет обратной ссылки в children родителя");
  }
  for (const ck of el.children ?? []) {
    const child = byKey.get(ck);
    if (!child) add(el, `children: ${ck} не найден`);
    else if (child.parentKey !== el.key) add(el, `children: у ${ck} другой parentKey`);
  }

  if (t === "group") {
    if (!onGrid(el.x) || !onGrid(el.y)) add(el, "начало группы не на сетке — вся внутренность уедет");
    if (!onGrid(el.w) || !onGrid(el.h)) add(el, "размер группы не кратен 20");
    const first = byKey.get((el.children ?? [])[0]);
    if (!first || first.type !== "rectangle") add(el, "первым ребёнком нет рамки-rectangle");
  } else if (t === "circle") {
    const r = el.radius;
    if (!(r >= GRID) || r % GRID !== 0) add(el, `radius ${r}: нужен кратный 20 и ≥ 20`);
    if (el.w !== 2 * r || el.h !== 2 * r) add(el, "w/h должны быть 2·radius");
  } else if (t === "line") {
    const dx = (el.x2 ?? 0) - (el.x1 ?? 0), dy = (el.y2 ?? 0) - (el.y1 ?? 0);
    if (Math.hypot(dx, dy) < GRID) add(el, "длина меньше клетки");
    const ortho = Math.abs(dx) < 1 || Math.abs(dy) < 1;
    if (ortho && ![el.x1, el.y1, el.x2, el.y2].every(onGrid)) add(el, "ортогональный отрезок не на сетке");
    const sw = el.strokeWidth ?? el.stroke_width;
    if (sw != null && sw < 0.5) add(el, `strokeWidth ${sw} < 0.5`);
  } else {
    if (!onGrid(el.x) || !onGrid(el.y)) add(el, "позиция не на сетке");
    if (el.w < GRID || el.h < GRID) add(el, "размер меньше 20");
    const fs_ = el.fontSize ?? el.font_size;
    if (t === "text" && fs_ != null && fs_ < 12) add(el, `fontSize ${fs_} — мелко для экрана`);
  }
}

const roots = els.filter(e => !byKey.has(e.parentKey));
const maxX = Math.max(...roots.map(e => (e.x ?? 0) + (e.w ?? 0)));
const maxY = Math.max(...roots.map(e => (e.y ?? 0) + (e.h ?? 0)));
if (maxX > 5000 || maxY > 5000) problems.push(`схема ${Math.round(maxX)}×${Math.round(maxY)} не влезает в 5000×5000`);

console.log(problems.length ? problems.slice(0, 100).join("\n") : "OK");
console.log(`элементов: ${els.length}, замечаний: ${problems.length}`);
```

## 12. Как проверить результат в редакторе

1. Открыть проект и схему, нажать «Импорт», выбрать файл. На непустой схеме редактор
   спросит «заменить или добавить».
2. Тост показывает разбивку по типам — сверить с контрольными числами выгрузки.
3. Включить зум 100 % и провести по паре объектов: элемент **не должен дёргаться** при
   первом перетаскивании. Дёрнулся — координаты не были кратны 20.
4. Взять кружок внутри группы и подвинуть на клетку: он обязан встать ровно на линию сетки.
   Встал между линиями — не выровнено начало группы (§3.2).
5. Проверить читаемость при «вписать в экран»: подписи должны читаться, линии не должны
   пропадать.
6. Сохранить, перейти на другую схему и вернуться: число элементов и картинка обязаны
   совпасть, метаданные (`lua_name`, `tech_object`) — сохраниться.
